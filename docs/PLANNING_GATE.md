# 코드 작업 전 기획 검수 결과

기준일: 2026-11-04. 이 문서는 **제작 착수 전의 검수 기록**이다. 당시에는 기획을 완료로 판정하지 않았다. 이후 사용자의 제작 착수 요청에 따라 [첫 항구 시범판](BUILD_STATUS.md)을 구현했다. 아래 0장 수치와 코드 진입 조건은 **착수 전 상태**이며 현재 구현 수를 뜻하지 않는다.

| 사용자가 확인을 요청한 항목 | 착수 전에 확인된 사실 | 당시 판정 |
| --- | --- | --- |
| 시작과 끝 | 출생 뒤 관찰 8장면, 첫 선택 9번째, 세 종료 이유와 결산 4단계를 정의했다. 한 항구 생애는 손실→성장→은퇴까지 예시를 썼다. | **구조 있음.** 다섯 출생×세 엔딩의 원고 연결은 미검증 |
| 이벤트 총수 | 착수 전 실제 게임 내장 **0개**. 고유 장면 카드 **339개는 임시 제작 목표**였다. 검토용 원고 3개만 별도로 작성했다. | **미달** |
| 분기 수 | 모드 2개, 출생 5묶음, 소속 7군·무소속, 목표 5종, 세계 규모 IF 2개, 종료 이유 3개를 설계했다. 이 수를 곱한 값은 실제 경로 수가 아니다. | **큰 갈래 정의.** 도달 가능한 경로 수 미확정 |
| 문장 가독성 | 예시 본문 3개는 100·103·106자, 각 두 문단이다. PC·휴대폰 선택 시안의 텍스트는 정적 글꼴 폭 검사에서 캔버스 밖으로 넘치지 않았다. 작은 글자 색을 고친 뒤 계산상 최저 대비는 4.97:1이다. | **샘플 치수·대비 통과.** 실제 화면·사람 읽기 미검증 |
| 그림의 설명력 | 한 항구 경로의 폭풍·수리·은퇴 그림 3장이 배·인물·나침반의 변화를 보여준다. | **한 사례 확인.** 다른 종족·소속·사건 미검증 |
| 성장 재미 | 기술·인연·책임·세계 영향이 다음 선택을 여는 규칙과 수리→구조선 예시가 있다. | **예시 있음.** 실제 보상 간격과 플레이 감각 미검증 |
| 독자적 UI/UX | 항해 일지에서 출발한 PC·휴대폰 선택 장면 시안과 성장 비교를 만들었다. 유리 카드·획일적 격자·편집기형 패널을 쓰지 않았다. | **방향 있음.** 실제 렌더링·접근성·사용성 미검증 |
| 10회 반복 | 한 생애 내 같은 사건 ID 중복 금지와 지난 생애 우선순위 규칙이 있다. 같은 목표의 6개 중 회차당 4개를 쓰면, 연속 두 회차에 최소 2개가 반드시 겹친다는 한계가 드러났다. | **불합격 위험.** 카드 풀 조정과 탁상 10회 검수 필요 |

## 바로잡은 설계 결정

1. 이전의 158장면 조각 계획은 공통 장면 재사용이 지나치게 커서 339장 목표로 바꿨다. 339라는 숫자도 최종 합격값이 아니다. 특히 목표 사건군의 필연적 중복을 해결해야 한다. [수량 근거](CONTENT_AUDIT.md)
2. 선택 장면 시안을 시작 막 9번째 장면으로 맞췄다. 그림에 균열이 보이지 않는 나침반은 원고에서도 ‘가족의 나침반’으로 적어 그림과 문장을 맞췄다. [세 장면 예시](SCENE_EXAMPLE.md)
3. AI가 만든 듯한 획일적 웹 디자인을 피한다는 사용자의 뜻을 [화면 기준](UX_ART_DIRECTION.md)에 반영했다. 섬과 바다의 분위기를 없애는 요구로 해석하지 않는다.

## 코드 작업으로 넘어가는 조건

1. 339장을 임시 숫자로 두고, 각 사건의 ID·진입 조건·선택 결과·후속·그림 키를 실제 목록으로 쓴다. 목표 사건군의 중복을 줄이도록 총량과 배분을 재산정한다.
2. 카드 연결표에서 원작 모드와 IF 모드의 도달 가능한 큰 경로를 세고, 다섯 출생 묶음·일곱 소속군·무소속·세 종료 이유마다 시작의 인연이나 문제가 결말에 돌아오는지 점검한다.
3. 같은 출생·소속·목표를 포함해 10회분 생애를 **카드 목록으로 탁상 진행**하고, 개인 사건 ID 중복과 ‘같은 이야기’ 느낌을 기록한다. 고정 역사 사건은 반복 항목에서 따로 표시한다.
4. PC·휴대폰의 시작·관찰·선택·성장·엔딩 화면을 실제 렌더링으로 보고, 그림만 보고 상황을 이해하는지, 위험 문구를 오해하지 않는지 사람에게 확인한다.
5. 원작 인물·직책·연표를 쓰는 카드마다 만화 화수·시기·장소·정보 경로를 확인한다. 미완결 부분의 미래를 원고에 넣지 않는다.

이 조건을 통과하기 전에는 40~60분 플레이타임, 10회 반복 만족, UI/UX 품질, 실제 분기 수를 검증 완료라고 표시하지 않는다. 시범판 제작은 시작됐지만 공개 배포와 전체 완성 판정은 별도다.
