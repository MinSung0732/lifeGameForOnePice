# 화면·문장·그림·성장 경험 기준

상태: 2026-11-04 제작 전 검수 기준. 사용자가 원하는 것은 원피스 세계의 한 사람을 살아 보는 화면이다. **AI가 일괄 생성한 듯한 획일적 웹 디자인과 Codex 제품을 연상시키는 화면 언어를 피한다.** 섬·바다 자체는 게임 세계의 일부로 사용할 수 있다. 실제 시안과 플레이 검수 전에는 UI/UX가 좋다고 판정하지 않는다.

## 1. 화면의 방향

기본 화면은 가상의 항해 기록·생활 일지를 읽는 감각으로 만든다. 원작 로고나 공식 지도·신문 디자인은 복제하지 않고, 게임만의 여백·선·종이색·바다색·도장 모양을 설계한다. 번쩍이는 그라디언트, 유리 카드, 똑같은 둥근 카드의 격자, 코드 편집기처럼 보이는 패널을 기본 스타일로 쓰지 않는다. 그림을 돋보이게 할 만큼만 장식을 둔다.

| 화면 | PC | 휴대폰 |
| --- | --- | --- |
| 시작 | 제목과 한 생애의 분위기를 보여주는 원본 그림, 그 아래 두 모드의 차이를 같은 크기로 제시 | 모드 설명을 짧게 줄이고 두 선택을 세로로 놓는다. 출생 추첨 전에 언제든 바꾼다. |
| 장면 | 큰 그림이 현재 장소와 행동을 설명하고, 옆의 짧은 본문·선택지가 이어진다. 나이·소속·목표는 작은 일지에서 본다. | 그림 → 본문 → 선택 순서. 주요 선택과 속도 조절은 엄지로 누르기 쉽고 겹치지 않는다. |
| 선택 결과 | 그림에서 변한 물건·표정·상황을 먼저 보여주고 텍스트로 결과를 확인한다. | 동일한 순서로 세로 배치하며 본문을 가리는 모달을 남발하지 않는다. |
| 엔딩 | 시작의 장소·물건이 달라진 그림으로 돌아온 뒤 생애 기록을 보여준다. | 한 장씩 넘기되 뒤로 돌아가 읽을 수 있다. |

모바일의 본문은 최소 16px, 충분한 줄 간격, 한 화면에 한 가지 현재 상황을 원칙으로 한다. 클릭 대상은 손가락으로 누르기 쉬운 크기로 잡고, 색만으로 위험·선택 가능 여부를 구분하지 않는다. 키보드 조작, 화면 읽기 순서, 대체 설명, 움직임 줄이기 설정을 시안부터 확인한다.

## 2. 문장을 짧게 쓰는 규칙

보통 장면 본문은 **90~220자, 두 짧은 문단 이하**를 목표로 한다. 중대한 전환점도 300자를 넘기기 전에 장면을 나눈다. 한 문장은 한 행동이나 사실을 전달하고, 시대 설명은 플레이어가 그 소식을 알 수 있는 장면에만 놓는다. 선택 문구는 길게 설명하지 않고 행동으로 쓴다. 위험과 대가가 있으면 선택지 바로 옆에 짧게 표시한다. 긴 설정 설명은 선택과 관계없는 본문에 끼워 넣지 않고 일지에서 선택적으로 읽게 한다.

예시 장면 본문: “폭풍이 지나간 아침, 가족의 배는 부두 아래에 걸려 있었다. 양육자는 가족이 쓰던 나침반을 손에 쥐고 있었다.”

예시 선택: “배 수리를 배운다” / “다른 배에 일자리를 구한다” / “항구를 떠난다”. 선택 직후에는 관계·기술·위치 중 무엇이 달라졌는지 한 문장으로 보여준다. 화면 폭 때문에 줄이 지나치게 길어지거나, 휴대폰에서 그림과 본문을 번갈아 찾게 되면 시안을 고친다.

## 3. 그림이 설명해야 하는 것

매 장면의 그림은 장식용 배경만이 아니다. **누가, 어디서, 무엇을 겪는지** 중 최소 두 가지를 글보다 먼저 알아볼 수 있어야 한다. 사건 카드에는 장소·인물·표정·소품·상태 변화의 그림 키를 붙인다. 대화·소문 카드도 말하는 사람과 정보가 온 경로를 시각적으로 구분한다. 공식 그림·로고·음악을 복사하지 않는다.

| 검수용 장면 | 그림에서 먼저 보여줄 정보 |
| --- | --- |
| 출생 | 종족과 고향의 생활 공간, 돌보는 사람, 주인공의 어린 모습 |
| 폭풍 뒤의 선택 | 부서진 배, 손에 남은 나침반, 서로 다른 세 행동의 방향 |
| 직책 상승 | 새 복장·배·함께 일하는 사람. 권한과 책임이 동시에 늘어난 모습 |
| IF 세계선 | 달라진 신문·깃발·사람들의 반응. 원작 모드와 혼동되지 않는 표시 |
| 엔딩 | 시작에서 보았던 물건·장소가 달라진 상태. 남은 사람과 일의 결과 |

첫 시안은 PC와 휴대폰 각각에서 시작·관찰·선택·성장·엔딩 화면을 보여준다. 그림만 5초 보고 상황의 핵심을 말할 수 있는지, 본문을 읽은 뒤 선택의 위험을 오해하지 않는지 검수한다. 그림이 추상적이거나 본문과 다른 일을 설명하면 에셋이나 사건 문장을 수정한다. 이 검수는 실제 시안이 생긴 뒤에만 완료할 수 있다.

## 4. 성장의 재미

성장은 전투력 숫자 하나가 아니라 **배운 일, 깊어진 인연, 맡은 책임, 세계에 남긴 영향** 네 방향으로 보인다. 배우지 않은 기술로 다음 사건을 해결할 수 없고, 오래 쌓은 기술·관계는 전혀 다른 선택을 연다. 승진·배·거점·도구·복장의 변화는 그림과 일지에 남는다. 실패와 부상도 새 선택이나 대가로 돌아온다.

한 회차에서 약 5~7장면마다 능력·관계·소속·목표 중 하나의 변화를 플레이어가 눈으로 확인하게 한다. 직책이 높아지면 명령권과 함께 지킬 사람·잃을 것이 늘어난다. 민간인의 성장은 가게·배·치료법·마을처럼 다른 형태의 성취로 보여준다. 성장 장면만 이어 붙여 반복 보상을 주지 않고, 같은 변화가 나중에 실제 문제 해결에 쓰이는지 검수한다.

## 5. 시안 현황과 전체 완성 전에 남은 확인

동쪽 바다 항구의 한 경로를 [PC 선택 화면](../design/scene-desktop.svg), [휴대폰 선택 화면](../design/scene-mobile.svg), [성장 전후 비교](../design/growth-before-after.svg)로 그렸다. [폭풍](../design/assets/storm-harbor.png) → [수리](../design/assets/repaired-harbor.png) → [은퇴](../design/assets/retirement-harbor.png) 그림은 같은 장소·배·나침반이 달라지는 검토용 예시다. [세 장면의 원고](SCENE_EXAMPLE.md)는 각각 100·103·106자이며, 시안의 글자가 캔버스 밖으로 넘치지 않는 것은 정적 글꼴 폭 검사로 확인했다. 작은 글자의 색 대비가 처음에는 부족해 색을 고쳤고, 해당 SVG 시안의 계산상 최저 텍스트 대비는 배경에 대해 4.97:1이다. [첫 항구 시범판](BUILD_STATUS.md)의 실제 화면과 사람의 읽기 테스트는 아직 확인하지 못했다.

1. 원고 샘플을 휴대폰 폭에서 실제 렌더링으로 읽고, 한 장면의 문장 길이와 선택 뜻을 타인이 이해하는지 확인한다.
2. PC·휴대폰의 시작·관찰·선택·성장·엔딩 화면을 실제 크기로 직접 보고 수정한다. 시범판의 HTML/CSS 화면은 구현했지만 실제 렌더링 검수는 남았다.
3. 10회 반복 검수로 개인 사건의 중복과 성장 경로의 차이를 확인한다. [이벤트 검수 기준](CONTENT_AUDIT.md)
4. 모드·종족·소속별 한 생애가 [처음과 끝](STORY_ARC.md)을 실제로 잇는지 원고 수준에서 확인한다.

이 네 항목의 결과가 나오기 전에는 UI/UX, 그림의 설명력, 10회 반복 재미를 **검증 완료**로 적지 않는다.
